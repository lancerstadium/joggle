# Design 0002: callable values and Call

Status: accepted

## Decision

Joggle has one executable operation:

```text
Call(callee: Val, arguments: Val...) -> Val...
```

`callee` has a concrete `(inputs...) -> results...` Type. A direct call, an
operator, a lambda call, a fn parameter call, and a call through a returned fn
are therefore the same IR node. `Op` does not store a `FnDecl`, opcode,
attribute dictionary, behavior object, or lowering hook.

This is the basis for generic libraries and source-defined passes: higher-level
code can receive and call a fn without registering another operation schema.

## Source surface

Fn types and typed lambdas use ordinary expression syntax:

```joggle
fn apply<T, U>(input: T, body: (T) -> U) -> U {
  return body(input);
}

fn use(input: i8) -> i16 {
  return apply(input, (x: i8) -> i16 => extend(x));
}
```

Parameter annotations on a lambda are mandatory. Its result may be inferred
from context or written explicitly. The body uses the normal expression,
overload, generic, and staging rules; there is no Lambda declaration, region
syntax, pattern AST, or builder-only language.

The expression-only body is deliberate. Composition uses ordinary nested
calls rather than a second statement-bearing lambda grammar. A fully annotated
lambda supplies a concrete callable Type during bottom-up inference, so a
self-contained nested call can constrain an enclosing generic call. Ambiguous
or context-dependent nested calls fall back to the existing top-down expected
Type path.

This inference is effect-safe: probing may evaluate source-only or Hermetic
Known expressions, but it cannot execute a Guarded native binding. Observable
compiler work must first occur at an explicit `@` binding; the resulting Known
value can then participate in nested inference without re-execution.

## Declared fn references

Overload resolution produces a callable `Val`, not an opcode. That value
contains:

1. the selected `Mod::FnDecl`;
2. its concrete callable Type;
3. every Known compile-time argument used to specialize it.

For example, in a tensor call, `input` and `weight` are Call arguments while
`strides` and `pads` are bindings of the callee value. They are not attributes
on `Op`. Generic substitutions are reflected by the concrete callable Type and
can later be retained explicitly when generic pattern matching needs their
names.

The public inspection boundary is:

```cpp
Val Op::callee() const;
std::optional<Mod::FnDecl> Val::referenced_fn() const;
std::vector<std::pair<std::string, Val>> Val::bindings() const;
```

`Fn::Edit::call(declaration, arguments)` is only construction convenience. It
partitions compiler-time and runtime arguments, creates the specialized
callable value, and then creates the same Call as `call(callee, arguments)`.

## Anonymous fns

An inline callable stores an immutable verified `Fn`, not retained source
syntax and not a synthetic Mod member. Residual captures are explicit edges of
the callable `Val`; the anonymous body receives them as trailing hidden
arguments. Its public callable Type contains only the source parameters and
results. Capture order follows first lexical use and participates in
verification, formatting, identity, dependency collection, dominance, and use
queries.

Effect tokens may not be implicitly captured: a stateful callback must expose
the token in its source signature. This preserves affine effect flow and keeps
the effect boundary visible to transformations.

No public `Lambda`, `Closure`, `Pattern`, or `Callable` class is introduced.

## Verification

For every Call, verification proves:

- the callee is a valid dominating Val with a callable Type;
- argument and result counts and Types equal that concrete signature;
- a declared reference has complete, unique, domain-correct Known bindings;
- the selected declaration and all bound Types belong to the Fn's Mod closure;
- a linked `Compiler` can reproduce the concrete signature from the
  declaration, bindings, and generic solver;
- an anonymous body has the same visible signature and a valid nested Fn;
- each anonymous-body hidden argument has the Type of its explicit capture;
- every capture dominates each use of the callable value;
- effect arguments remain explicit and affine.

Construction performs cheap local checks. The linked Compiler performs checks
that require executing user-defined compile-time type functions. This avoids a
second partial evaluator inside `Fn::Edit`.

## Formatting and identity

Direct callees format as their selected declaration with compile-time bindings
written as named arguments. Dynamic callees format as their local value name.
Single-expression anonymous fns format as typed lambdas. Canonical identity
includes callee kind, declaration identity, bindings, callable Type, argument
edges, results, control flow, and nested bodies.

## Staging

Constructing or calling a callable value does not execute host code. Only
explicit `@call(...)` requests compiler-time evaluation. A typed lambda passed
to a compiler fn in the `fn` domain travels as a verified `Fn` object rather
than scalar metadata.

## Gates

1. [complete] Store exact declared and anonymous fns in typed Vals.
2. [complete] Make `Op::callee()` a Val and verify callable dominance.
3. [complete] Move compile-time arguments from Op properties to callee
   bindings.
4. [complete] Call a fn parameter with ordinary source syntax.
5. [complete] Preserve direct/indirect Calls through formatting, cloning,
   replacement, resolution, and dependency collection.
6. [complete] Closure-convert residual captures while rejecting implicit
   effect capture.
7. [complete] Infer unique nested call results from fully annotated callable
   arguments without speculatively executing Guarded native bindings.
8. [planned] Retain structured loop bodies as closure-converted callable Vals
   until an explicit CFG pass.
