\section{Discussion}
\label{sec:discussion}

\paragraph{Extension boundaries.} A mod groups a feature's functions behind one
public interface independently of compiler stages. For a numeric-format
change, analysis, lowering, and packing can share an owner while source fragments
subdivide implementation. The package study shows that direct publication
reduces integration code; subsequent edits remain local in all three systems.

\paragraph{Reuse boundaries.} Within a retained graph, observations and effects
select stages; across imported revisions, specialization signatures select
reusable prepared bodies. These are distinct reuse units. Removing preparation
work shifts the remaining update cost toward emission and native compilation,
identifying the next boundary for optimization.

\paragraph{Consistent publication.} Mods determine which implementation is
visible; calls record what it observes; transactions publish the resulting graph
and dependency records together. External inputs enter call identity through
typed arguments and environment revisions. Consequently, extension, ownership,
and reuse share an explicit publication boundary.
